# Medicine-
Приложение оперативного оповещения медицинской команды (ТЗ v1.0).

Диспетчер отправляет вызов выбранной команде, участники получают push-уведомление
и подтверждают его кнопкой **«Я УВИДЕЛ»**, диспетчер видит статус каждого получателя.
SMS-резерв (п.10 ТЗ) по решению заказчика не используется.

```
mobile/   мобильное приложение (Expo / React Native, Android и iOS)
server/   сервер (Node.js 22, Express, SQLite) — вызовы, push, история
```

## Архитектура

```
Диспетчер ──POST /api/calls──▶ Сервер ──Expo Push (FCM/APNs)──▶ Участники
                                 │  ▲                                │
                                 │  └──POST /api/calls/:id/ack───────┘ «Я УВИДЕЛ»
                                 │
                                 ├─ через 5 мин: вызов завершается
                                 └─ очистка: получатели — 24 ч, вызовы — 72 ч
```

* Сервер хранит данные в SQLite (встроенный модуль `node:sqlite`, без нативных зависимостей).
* Очистка истории работает по данным в базе, поэтому переживает перезапуск сервера.
* Push-уведомления отправляются через Expo Push Service, который доставляет их
  на Android (Firebase Cloud Messaging) и iOS (Apple Push Notification service)
  при открытом, свёрнутом и закрытом приложении.

## Сервер

Требуется Node.js ≥ 22.13.

```bash
cd server
npm install
cp .env.example .env      # при необходимости измените настройки
npm run dev               # разработка
npm test                  # тесты по критериям готовности ТЗ
npm run build && npm start
```

Или в Docker:

```bash
docker build -t team-alert-server server
docker run -p 3000:3000 -v team-alert-data:/data --env-file server/.env team-alert-server
```

### Переменные окружения

| Переменная | Описание |
|---|---|
| `PORT` | Порт HTTP (по умолчанию 3000) |
| `DB_PATH` | Файл базы SQLite (по умолчанию `./data/team-alert.db`) |
| `SEED_TEAMS` | Команды, создаваемые при первом запуске, через запятую |
| `EXPO_ACCESS_TOKEN` | Токен Expo, если включена Enhanced Push Security |

В продакшене сервер должен работать за HTTPS (например, nginx / Caddy с сертификатом).
iPhone по умолчанию не подключается к серверам без HTTPS.

### API

Все методы, кроме регистрации, требуют заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/register` | Регистрация `{name, phone, role}` → `{token, user}` |
| GET / PATCH / DELETE | `/api/me` | Профиль; изменение `{name, phone, role, teamId}`; удаление своего аккаунта |
| PUT | `/api/me/push-token` | Push-токен устройства |
| POST | `/api/logout` | Выход |
| GET / POST | `/api/teams` | Список команд / создание команды (диспетчер) |
| GET | `/api/teams/:id/members` | Состав команды |
| GET | `/api/participants` | Все участники (для добавления в команду) |
| PUT | `/api/users/:id/team` | Добавить / перевести (`teamId`) или убрать из команды (`null`) |
| DELETE | `/api/users/:id` | Полностью удалить участника |
| POST | `/api/calls` | Вызов: `{kind: "car"}` или `{kind: "place", place}` |
| GET | `/api/calls/active` | Активные вызовы (диспетчера / участника) |
| GET | `/api/calls/:id` | Вызов; диспетчеру — со статусами получателей |
| POST | `/api/calls/:id/ack` | «Я УВИДЕЛ» |
| GET | `/api/calls/history` | История за 3 дня |

## Мобильное приложение

```bash
cd mobile
npm install
cp .env.example .env      # EXPO_PUBLIC_API_URL — адрес сервера
```

Push-уведомления не работают в Expo Go, поэтому нужна собственная сборка (development build):

1. Создайте проект в [Expo](https://expo.dev) и привяжите приложение: `npx eas-cli@latest init`
   (идентификатор проекта запишется в `app.json` → `extra.eas.projectId`).
2. **Android:** создайте проект Firebase, добавьте Android-приложение `com.medicine.teamalert`,
   положите `google-services.json` в `mobile/` и укажите `"googleServicesFile": "./google-services.json"`
   в `app.json` → `android`; загрузите ключ сервисного аккаунта FCM v1 в Expo
   (`npx eas-cli@latest credentials`).
3. **iOS:** нужен Apple Developer аккаунт; ключ APNs EAS создаст сам при первой сборке.
   Пошаговая инструкция для iPhone — в [docs/apple.md](docs/apple.md).
4. Сборка:
   ```bash
   npx eas-cli@latest build --profile development --platform all   # для разработки
   npx eas-cli@latest build --profile preview --platform android    # APK для тестирования
   npx eas-cli@latest build --profile production --platform all     # для магазинов
   npx expo start                                                   # dev-сервер для development build
   ```

Измените `bundleIdentifier` / `package` в `app.json`, если нужен другой идентификатор приложения.

## Соответствие критериям готовности

| № | Критерий | Реализация |
|---|---|---|
| 1 | Регистрация как диспетчер или участник | `register.tsx`, `POST /api/register` |
| 2 | Только одна команда | у пользователя одно поле `team_id`; добавление в новую команду убирает из старой |
| 3 | Диспетчер выбирает любую команду | `teams.tsx`, `PATCH /api/me {teamId}` |
| 4 | Управление составом | `team.tsx`: добавить, убрать, удалить, перевести |
| 5 | «ОТПРАВИТЬ ВЫЗОВ» без подтверждения | `dispatcher.tsx` → `POST /api/calls {kind: "car"}` |
| 6 | «УКАЗАТЬ МЕСТО» → «Другое» | `place.tsx` |
| 7 | Push всем участникам | `Service.sendPushes`, канал Android `calls` (звук + вибрация) |
| 8 | «Я УВИДЕЛ» | `call/[id].tsx` → `POST /api/calls/:id/ack` |
| 9 | Диспетчер видит подтверждения | `call/[id].tsx`, обновление каждые 2 с: УВИДЕЛ / НЕ ПОДТВЕРДИЛ |
| 10–11 | SMS через 10 с только неподтвердившим | отменено заказчиком |
| 12 | Завершение через 5 минут; новый вызов — только после завершения | `expires_at`, проверка в `Service.createCall` |
| 13 | Независимость диспетчеров | ограничение действует на пару «диспетчер + команда» |
| 14–15 | История 3 дня, получатели 24 часа | `Service.cleanup`, фильтрация в запросах |
| 16 | Изменение данных без нового аккаунта | `PATCH /api/me` обновляет существующую запись |
| 17 | Android и iOS | Expo / React Native, сборка через EAS |

Каждый критерий серверной логики покрыт тестом в `server/test/api.test.ts`.

## Принятые решения

* **Повторная регистрация** с уже известным номером телефона не создаёт нового пользователя,
  а входит в существующий аккаунт (обновляя имя и роль). Так можно восстановить доступ после
  переустановки приложения. По ТЗ отдельной проверки нет, поэтому номер телефона не подтверждается
  кодом из SMS — при необходимости это можно добавить позже.
* **Состав команды** — пользователи с ролью «участник». Для диспетчера поле «команда» означает
  выбранную им команду; диспетчеры вызовы не получают.
* **Команды** может создавать любой диспетчер (отдельной роли администратора нет). Команды из
  `SEED_TEAMS` создаются при первом запуске.
* **Удаление участника**: «Убрать» исключает из команды (аккаунт остаётся, его можно добавить снова),
  «Удалить» полностью удаляет аккаунт. Получатели уже отправленных вызовов хранятся снимком и не меняются.
* **Ограничение на новый вызов** действует для пары «диспетчер + команда»: другие диспетчеры
  (и другие команды) не блокируются.
* «К машине» на экране выбора места отправляет тот же вызов, что и кнопка «ОТПРАВИТЬ ВЫЗОВ».
* Участник может подтвердить вызов, только пока он активен (5 минут).
* **SMS-резерв** (п.10–11 ТЗ) отключён по решению заказчика; номер телефона остаётся в профиле.
* **Удаление аккаунта** самим пользователем добавлено по требованию App Store (правило 5.1.1(v)).
* Push используют обычный звук и уровень важности: режимы «Не беспокоить» и беззвучный не обходятся.
